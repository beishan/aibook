# 网站自动入库规则

在「书籍爬虫 → 采集网站 → 自动入库配置」中为每个网站独立设置开关、入库格式和匹配规则。配置归属当前账户，保存于服务端，同一账户跨设备共享。默认关闭。

规则之间为 **或**：任意规则命中即可自动入库。同一规则的子表达式之间为 **且**：所有子表达式都满足才命中该规则。

| 子表达式 | 匹配方式 |
| --- | --- |
| 关键词包含 | 书名、作者、简介任一字段包含任一关键词；英文不区分大小写，按普通文字匹配 |
| 书籍标签命中 | 书籍的任一标签与配置中的任一标签精确匹配；使用现有换行、逗号、中文逗号、顿号分隔方式 |
| 书籍章节数 | 使用采集目录的总章节数，支持大于、大于等于、等于、不等于、小于、小于等于 |

例如以下两条规则任意一条命中即可：

1. 关键词包含「神话」「传说」中的任一项，且书籍章节数大于 10。
2. 标签精确命中「aaa」，且书籍章节数大于 20。

正文采集成功（包括后续续采或更新成功）时读取网站当前配置并判断。暂停或存在失败章节时不触发；保存配置不会立即处理历史书籍。被忽略或加入黑名单的书籍不通过网站规则入库。未填写的旧配置按关闭处理，空规则或空子表达式不能开启自动入库。

可多选结构化章节、TXT、EPUB。单本书已显式开启自动入库时，优先沿用单本设置与入库格式；未开启单本自动入库的书籍仍可通过网站规则命中。既有已入库书籍的自动同步保持生效，命中网站规则时复用入库同步，避免重复创建同来源书籍。

网站全部配置导出包含可选的 `autoImport` 字段，旧版导入文件没有该字段时保持关闭：

```json
{
  "enabled": true,
  "formats": ["STRUCTURED"],
  "rules": [
    {
      "name": "神话与传说",
      "expressions": [
        { "type": "KEYWORD", "values": ["神话", "传说"] },
        { "type": "CHAPTER_COUNT", "comparison": "GT", "chapterCount": 10 }
      ]
    },
    {
      "name": "指定标签",
      "expressions": [
        { "type": "TAG", "values": ["aaa"] },
        { "type": "CHAPTER_COUNT", "comparison": "GT", "chapterCount": 20 }
      ]
    }
  ]
}
```

接口为 `GET/PUT /api/crawler/sites/{id}/auto-import`，按当前账户检查网站所有权。最多 50 条规则，每条最多 20 个子表达式，每个关键词或标签条件最多 50 项，单项最多 200 字。配置最大 128 Ki 个字符，超限由服务端拒绝。

配置写入网站新增的 `auto_import_rules_json` TEXT 字段，由现有 Hibernate schema update 管理。使用独立更新语句保存，常规网站编辑和后台采集的旧实体不会覆盖规则。匹配仅支持固定条件，不执行用户输入的脚本、表达式语言或正则表达式。

实现前评估了 Easy Rules（MIT，维护模式）与 Drools（Apache-2.0，通用规则引擎）。对三类固定条件，通用引擎会增加依赖、运行时和集成维护成本；本功能复用现有 Java、Jackson、Vue 和 Element Plus，无新增依赖、外部代码或服务。

- [Easy Rules 项目](https://github.com/j-easy/easy-rules)
- [Apache Drools](https://kie.apache.org/drools/)
