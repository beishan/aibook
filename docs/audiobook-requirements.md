## 1. 目标与边界

在现有 Spring Boot、PostgreSQL、Vue、Android 和 iOS 工程中增加有声书管理与收听能力，复用账户、权限、书库、标签、收藏、目录扫描配置、任务调度与备份体系，保留现有部署拓扑。

“有声书”首先指已有音频文件。媒体探测工具可作为现有后端镜像内按需调用的子进程，客户端可采用成熟播放库；这不等于增加独立服务。用户已同意在现有后端镜像中引入 ffprobe，并在 Android 客户端引入 Media3；其他候选依赖仍按 AGENTS.md 的规则处理。

### 1.1 首个可发布范围（P0—P3）

- NAS 目录扫描、单文件上传、多文件上传与导入预览。
- 单文件整本、多文件分集、单音轨多章节；目录内 cover.jpg 等封面读取。
- 作品关联、多个演播版本、演播者、语言、简介、版本说明、总时长和章节资料。
- Web 播放、暂停、拖动、倍速、前后跳转、连续切集、睡眠定时、音频书签及断点续播。
- 账户进度与偏好持久化，首页继续收听、书库筛选、详情收听入口和全局迷你播放器。
- 优先验证 MP3、AAC 编码的 M4A/M4B；识别容器与实际编码后再决定能否播放，不按扩展名承诺兼容性。

### 1.2 后续范围

- P4：Android/iOS 原生后台、锁屏、耳机控制和中断恢复。
- P5：离线下载、进度补传、收听统计；按实际需要增加后台格式转换。
- 外部客户端协议另行评估，不假设提供 OPDS 就能同步音频进度。

### 1.3 暂不包含

TTS 配音、播客、在线音频采集、字幕识别、AI 文本音频对齐、跨演播版本自动定位和实时 HLS 转码。新增范围须补充需求及验收，不能作为首期隐含任务。

## 2. 产品规则

1. 一本作品可仅有电子版、仅有有声版，或同时拥有两者。
2. 每个演播者、语言、完整版/删节版组合可建立独立有声版本。
3. 书名相同不自动合并；用户在导入预览确认新建作品或关联现有作品。
4. 一个有声版本包含多个音轨，音轨是实际文件；章节是时间区间，两者不等同。一章跨文件时允许使用多段定位。
5. 阅读与听书的进度、完成状态和实际使用时长分别保存，不直接修改现有文字阅读状态。
6. 更换有声版本不按百分比或章节序号自动跳转；返回旧版本恢复其自身位置。
7. 文件缺失标记异常，保留版本、书签和进度；回收及恢复沿用现有原文件保护规则。
8. 详情展示阅读/收听能力和版本选择；纯有声书不出现不可用的电子书下载、解析或阅读操作。
9. 互斥选择遵循项目滑块分段控件规范，支持键盘、焦点、窄屏滚动和减少动画偏好。Android 按钮反馈不用按压阴影。

## 3. 现有代码适配与数据设计

### 3.1 兼容策略

- Book 继续作为统一作品入口；现有 BookVersion 保持电子书单文件职责。
- Book 当前 format/filePath 非空，纯有声书需进行兼容迁移：明确其为电子书兼容字段并允许无电子版本时为空，不填充虚假路径。
- 逐项检查 BookDTO、版本解析、详情、列表排序、扫描去重、文件下载、格式转换、OPDS、书籍合并与回收逻辑；旧客户端不得收到伪装成电子书的音频记录。
- 明确旧客户端的能力过滤或不支持提示，并验证旧电子书数据及接口保持正常。
- 数据迁移以新增表为主；迁移前后验证历史记录，回退应用前评估纯有声书记录与可空字段对旧版本的影响，不盲目降级。

### 3.2 建议数据对象

| 对象 | 职责与关键字段 |
|---|---|
| audiobook_editions | book_id、版本名称、演播者、语言、说明、总时长、内容修订号、可用状态 |
| audio_tracks | edition_id、稳定 ID、路径、顺序、时长、大小、容器、编码、指纹、可用状态 |
| audio_chapters | edition_id、标题、顺序和时间区间；跨音轨用有序定位段表达 |
| listening_progress | user_id、edition_id、track_id、文件内毫秒位置、状态、修订号、最后收听时间 |
| listening_sessions | 用户、设备、版本、会话代次、事件序号、累计有效收听时间、有效期及结束状态 |
| audio_bookmarks | 用户、版本、音轨、毫秒位置、标题和备注 |
| listening_daily_activity | 用户、日期和实际收听时长，保留明确统计时区 |

开发时落实外键、账户/版本进度唯一约束、音轨顺序索引、查询索引与迁移策略。跨音轨章节的定位段可使用独立子表，具体结构在 P0 固定。

播放速度、前后跳转秒数和常用定时长度复用账户偏好；浏览器存储仅用作缓存或未登录暂存。睡眠定时的当前截止时间属于播放会话，不能误同步成其他设备正在运行的定时器。

## 4. 扫描、上传与资料管理

- 在现有目录配置中增加内容类型，区分电子书和有声书扫描策略。
- 新增 AudioScanService、AudiobookImportService，复用现有调度和任务基础设施；不将 MP3 直接加入电子书逐文件解析流程。
- 默认按目录识别一个有声版本，单文件可单独入库；多光盘、多级目录、混合内容允许用户在预览调整分组。
- 排序优先级：手工顺序、可靠的光盘号/轨道号、文件名自然排序。中文数字辅助识别必须可校正。
- 分别保留提取资料和用户覆盖值；重扫不覆盖手工排序、标题或章节。
- 用路径、大小和修改时间筛选变化文件，必要时计算完整指纹；重扫幂等，移动重关联有歧义时由用户确认。
- 上传使用临时文件，完成后原子提交；扫描避开仍在复制的文件。多文件入库支持取消、失败重试和部分结果检查。
- 原文件只读；封面缓存、任务结果、临时文件与未来派生音频放入应用数据目录。
- 所有任务按现有权限隔离；单个损坏文件不能阻塞整个扫描。

## 5. 媒体接口、鉴权与播放

### 5.1 接口契约

| 接口类别 | 操作 |
|---|---|
| 有声版本 | 创建、查询、编辑、关联作品、回收与恢复 |
| 音轨/章节 | 查询、排序、编辑、重新探测 |
| 入库任务 | 扫描预览、确认、任务状态、取消与重试 |
| 播放会话 | 创建、续期、心跳、结束与接管 |
| 媒体内容 | 经授权的 GET/HEAD 与 Range 读取 |
| 听书进度 | 获取、保存、听完、重新开始 |
| 音频书签 | 创建、查询、修改与删除 |

P0 固定请求响应、分页、错误码、幂等和修订冲突语义。现有文字阅读接口保持兼容。

### 5.2 流播放要求

- 首版使用普通 HTTP 文件流，不增加切片服务；大文件不整本加载进内存。
- 验证普通请求、HEAD、单 Range、后缀 Range、无效 Range，以及 206/416、Content-Range、Content-Length、ETag、If-Range。
- 当前 BookController 内容接口提供 FileSystemResource 和 Accept-Ranges，可参考但必须通过真实请求验证完整行为。
- 测试代理后的拖动、断线恢复、源文件变化、长时间播放及凭证续期。
- 当前 JWT 支持查询参数；音频新增用途受限、可续期、可撤销的播放凭证，绑定用户和允许访问的版本，不将长期登录 JWT 放入音频 URL。
- 每次读取检查权限和可用状态；回收、账户停用或权限变化后拒绝新读取。规范化路径，约束可访问根目录，处理符号链接逃逸。
- 播放凭证在应用及反向代理日志中脱敏；兼容当前安全响应头和同源策略。

## 6. 进度与会话规则

- 精确位置使用稳定音轨 ID 加文件内毫秒数；整体百分比仅作展示。
- 心跳建议 10—15 秒一次；暂停、拖动、切集及时保存；页面关闭保存不能作为唯一保障。
- 请求包含会话 ID、事件序号、内容修订号和服务端进度修订号；重复事件幂等，旧序号不能覆盖新位置。
- 新设备先获取最新位置；会话接管后旧会话不能覆盖新会话的进度。
- 主动回听是合法操作，不采用“永远取最远进度”。
- 离线事件与服务器冲突时保留两份位置供选择，不仅依据客户端时钟判定。
- 内容替换、删除音轨、修改顺序后通过内容修订号识别旧定位，不静默跳到错误章节。
- 媒体位置和实际收听时长分别累计；暂停、缓冲、拖动、倍速和重复心跳不造成虚增；并发会话的重叠时间不重复计入账户统计。
- 睡眠定时依据截止时间或章末事件执行，验证后台计时限制，不只依赖 Web 定时回调次数。

## 7. Web 与移动端任务

### 7.1 Web

建议新增全局 audioPlayer store、播放生命周期服务、AudioMiniPlayer、AudioPlayer、AudioChapterList、AudiobookImport 和收听页面。

播放器挂在应用级生命周期，路由页面连接状态；切换页面不重建音频元素。处理底部 Dock、弹窗、窄屏、安全区域与键盘焦点。支持系统媒体控制的浏览器采用渐进增强，浏览器锁屏能力按实测描述。

### 7.2 Android / iOS

Android 候选 Media3/ExoPlayer，播放器运行在媒体服务；iOS 候选 AVPlayer 与后台音频会话。播放服务独立于页面生命周期，覆盖后台、锁屏、耳机、蓝牙、音频焦点、来电、耳机拔出和系统回收后的恢复。

### 7.3 离线

下载队列支持取消、断点续传、完整性校验、空间限制和清理。离线文件按账户隔离；退出或切换账户后不能通过旧入口访问。保存离线事件队列，联网后依照修订协议补传。大文件保存在设备文件系统，不放入账户偏好或浏览器 localStorage。

## 8. 候选依赖、部署与资源

| 候选 | 范围 | 收益与风险 |
|---|---|---|
| ffprobe | 现有后端镜像内按需子进程 | 提取编码、时长和章节；增加镜像与媒体解析维护成本，需限制超时、并发、输入及输出 |
| FFmpeg | 后续后台转换任务 | 生成兼容副本；增加 CPU/磁盘开销，许可证取决于具体编译配置 |
| Media3 | Android 客户端库，Apache-2.0 | 原生播放与媒体控制；需验证系统版本、设备和离线行为 |
| AVFoundation | iOS 系统框架 | 原生播放；需实现后台会话与中断恢复 |
| Web 原生音频 API | 现有 Vue 应用 | 无需额外播放器库；后台行为和编码支持存在浏览器差异 |

首期默认直放，不做实时转码。音频探测使用服务内独立受限执行器，初始并发建议为 1，并限制任务超时和输出大小；进度及任务状态持久化，重启后可恢复或重试。播放不得排队等待探测任务。

转换阶段另行增加磁盘配额、任务取消、重试和缓存清理。备份明确区分数据库、原始音频和可重建派生文件；恢复演练验证版本、路径、书签与进度关系。

| P4 Android | 原生播放服务、后台/锁屏/耳机、中断和续期 | 锁屏持续播放；来电、断网、耳机、系统回收行为符合预期 | 5—8 |

| P5 离线及统计 | 下载、校验、清理、离线补传、冲突选择、统计 | 离线后同步不覆盖新进度；重复请求和并发不重复统计 | 6—10 |

依赖顺序为 P0 → P1 → P2 → P3 → P4 → P5。首轮 P0—P3 预计 16—24 人日；估算基于单人开发、已有工程正常构建和素材齐备，含针对性测试，不含应用商店审核、额外转码及外部协议开发。P0 完成后按 NAS 与格式实测修订，不作为交付日期承诺。

首个可发布版本以 P3 验收为门槛；手机日常后台收听以对应平台 P4 验收为门槛，不能用手机浏览器替代原生验收。

## 10. 验证矩阵与发布要求

- 兼容回归：电子书查询、详情、阅读、版本、下载、扫描、转换、合并、OPDS 与回收。
- 入库测试：自然排序、多光盘、重扫、文件移动、上传中断、缺失与损坏、手工覆盖保留。
- 权限测试：跨账户版本、音轨、进度、书签和播放凭证访问均被拒绝。
- 流测试：真实 HTTP Range、反向代理、长音频随机跳转、内容更新、连接中断和过期凭证。
- 同步测试：重复/乱序事件、主动回听、接管、旧会话、内容修订、离线冲突和设备时间偏差。
- 移动实机：锁屏、后台、来电、耳机与蓝牙、网络切换、睡眠定时、系统回收与重启恢复。
- 运维验证：目标 NAS 探测与播放资源测量、备份恢复、升级及兼容回退评估；记录硬件、素材及测试条件，不预先承诺未知并发数。
- 修改服务签名时搜索并同步 Mockito stub、verify 与断言；执行受影响测试及阶段必要构建。
- 每个实际发布阶段同步 frontend/src/content/user-guide.md、需求变更记录及 SemVer 版本；涉及说明时执行 npm run test:user-guide。
- 开发完成通过必要验证后提交并推送，仅包含对应需求文件，使用中文提交信息并核对远端提交。
