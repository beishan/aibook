# 需求变更记录

本文件用于持续记录项目开发需求及完成情况，最新记录置于最上方。

## 记录规则

- 每项开发需求使用唯一编号：`REQ-YYYYMMDD-NNN`。
- 开始开发时可先登记为“进行中”；开发完成并验证后更新为“已完成”。
- 每条记录至少包含需求时间、完成时间、需求内容、完成情况、主要改动和验证结果。
- 需求取消、延期或部分完成时，应如实填写状态及未完成原因。
- 仅讨论方案、未产生项目变更的咨询不记入本文件；方案进入开发后再登记。

## 状态说明

| 状态 | 说明 |
|---|---|
| 待处理 | 已确认需求，尚未开始开发 |
| 进行中 | 正在开发或验证 |
| 部分完成 | 已交付部分内容，仍有明确未完成项 |
| 已完成 | 功能开发和必要验证均已完成 |
| 已取消 | 需求已明确取消 |

### REQ-20260804-007 修正 Linux/NAS 内存占用统计口径

- 需求时间：2026-08-04
- 完成时间：2026-08-04 15:49:13 CST
- 状态：已完成
- 需求内容：修复 NAS 物理机实际约占用 9.9G，但系统信息错误显示约占用 30G 的问题。
- 完成情况：Linux 宿主机内存改为按 `MemTotal - MemAvailable` 计算，避免把可回收缓存计入实际占用；容器内存同步扣除 cgroup 中的可回收文件缓存。
- 主要改动：
  - Linux 环境优先读取 `/proc/meminfo` 的 `MemAvailable`，其他系统继续使用 JVM 可见指标兜底。
  - cgroup v2 扣除 `inactive_file`，cgroup v1 扣除 `total_inactive_file`，缺少统计项时保持原有兼容行为。
  - 系统信息页补充内存统计口径说明。
  - 增加宿主机 32G 内存、cgroup v1 和 cgroup v2 缓存扣除测试。
- 验证结果：后端 95 项测试通过；前端生产构建通过；`git diff --check` 通过。

### REQ-20260804-005 系统设置展示系统资源占用

- 需求时间：2026-08-04
- 完成时间：2026-08-04 15:19:57 CST
- 状态：已完成
- 需求内容：在系统设置的系统信息中展示 CPU、内存和磁盘资源占用，并按 Sol 规划、Terra 执行。
- 完成情况：管理员可查看应用可见范围内的资源使用情况；普通用户不会看到资源卡且接口拒绝访问。
- 主要改动：
  - 新增仅管理员可访问的 `GET /api/system/resources`，不影响原有运行时接口。
  - Linux Docker 环境优先读取 cgroup v2，并兼容 cgroup v1；CPU 使用无阻塞差值采样，首次采集返回空值；无法读取时退回 JVM 可见的操作系统指标。
  - 内存优先使用容器限额；磁盘按可访问扫描目录的文件系统去重统计，不返回真实路径，无有效目录时统计应用工作目录。
  - 单项采集异常返回 PARTIAL/UNAVAILABLE，不会导致接口 500，结果短缓存 3 秒。
  - 系统信息页增加管理员资源卡、范围及可用状态说明、阈值颜色进度条、容量、采集时间和手动刷新；信息页可见时每 10 秒刷新，并防止并发请求和连续错误提示。
- 验证结果：后端 93 项测试通过（包含 cgroup v2/v1、小数 CPU 配额、缓存、磁盘去重、状态降级和管理员权限测试）；前端生产构建通过；`git diff --check` 通过。
