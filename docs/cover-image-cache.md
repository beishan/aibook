# 书库封面缩略图与缓存

书库卡片请求 `GET /api/covers/{filename}?width=320`，列表请求 `width=96`。
远程封面使用 `/api/covers/proxy?url=...&width=320`（列表同样使用 96）。
不传 `width` 时继续提供原图，因此书籍详情页和已有客户端无需调整。
仅接受 96、320 两档，其他尺寸返回 HTTP 400。

## 生成与显示

- 按比例缩小，不放大、不裁切；高度最多为对应宽度档位的两倍。
- 生成 JPEG，透明区域填白；GIF 使用第一帧，原图不变。
- 使用 Java 21 自带 ImageIO。默认 JDK 无法解码的 WebP、异常图片、超大像素图片，以及转换后体积更大的图片回退到原图。
- 同时最多解码两张图片，最多等待空闲解码名额 2 秒，繁忙时回退原图。回退响应不使用长期浏览器缓存，后续访问可重试。
- 缩略图按源文件路径、修改时间、文件长度和尺寸生成缓存键；上传替换仍使用现有唯一文件名，旧缓存定期回收。
- 页面仍保留 200 毫秒封面展示缓冲和前 12 本预加载，其他图片使用浏览器懒加载。

## 远程封面

首次访问在请求中下载，下载成功后保存到磁盘。后续请求直接使用缓存，重启服务后仍可复用。
缓存满 7 天后，先返回现有图片，再由后台线程刷新；刷新失败保留旧图，5 分钟内不重复发起刷新。
后台刷新最多 2 个线程、32 个排队任务，前后台总下载并发最多 4 个。
单张下载限制为 10 MiB，连接超时 5 秒、单次读取超时 10 秒，最多跟随 3 次跳转。
代理仅接受 HTTP/HTTPS，检查每次跳转的目标地址，拒绝回环、内网等地址以及非图片响应。

## 磁盘与清理

缓存位于 `${app.upload.dir}/${app.cover.dir}/.cache/v1/`：

- `thumbnails/`：生成的 JPEG 缩略图。
- `remote/`：远程封面的下载缓存。

Docker 默认目录为 `/app/uploads/covers/.cache/v1/`，沿用现有 uploads volume。
启动 1 分钟后开始检查，之后每小时清理一次：回收超过 30 天的缓存，并按生成时间从旧到新回收超过容量预算的部分。
默认预算 512 MiB，可使用 Spring 配置 `app.cover.cache.max-bytes`（环境变量 `APP_COVER_CACHE_MAX_BYTES`）调整。
容量为定期清理预算，两次清理间可以短暂超限。清理范围仅限缓存目录，不修改原封面、书籍文件或数据库。

首次下载和缩图仍有耗时；本功能不对整个书库提前下载或批量生成。外网下载速度与 NAS 实机响应速度需在部署环境中测量。

## 方案选择

评估过 [Thumbnailator](https://github.com/coobird/thumbnailator)：MIT 许可证，单个 JAR、无外部依赖，提供更丰富的缩放与图片处理能力。
本需求只使用固定尺寸缩放，沿用 [Java ImageIO](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/javax/imageio/package-summary.html) 与项目已有 Caffeine，未添加依赖或复制第三方代码。
