# 爬虫 Mihomo 节点管理

入口：采集任务 → 队列配置 → 管理执行器 → **Mihomo 节点**。

## 连接与启用

1. 填写控制 API 地址，例如 `http://192.168.31.155:9111`，以及 API 密钥。
2. 填写后端容器能访问的 HTTP 代理入口地址。这是实际采集流量的入口，不能填写控制 API 端口。
3. 点击“连接并刷新节点”，选择 `Selector` 类型代理组。
4. 勾选具体节点并排序，保存后该执行器自动启用 Mihomo 模式。
5. 可以检测已选节点或手动切换。API 密钥只保存在服务端，读取配置不会返回密钥；留空保留原值，勾选清除可移除密钥。

配置通过执行器所属队列绑定账户。切换到其他代理模式可在执行器编辑界面完成，Mihomo 配置仍保留。

建议建立专用入口和代理组，避免改变其他应用的出口。将下面内容合并到现有 Mihomo 配置相应区块，机场提供者名称替换为实际值，不要覆盖现有配置：

```yaml
proxy-groups:
  - name: 爬虫专用
    type: select
    use:
      - 你的机场提供者名称

listeners:
  - name: crawler-http
    type: http
    listen: 0.0.0.0
    port: 7895
    proxy: 爬虫专用
```

后端和 Mihomo 在同一 Docker 网络时，代理地址通常为 `http://mihomo:7895`，其中 `mihomo` 替换为服务名。跨容器访问不能使用后端自身的 `localhost`。实际使用 IP 地址时需要相应端口可达。

应用不会自动修改 Mihomo 配置、更新机场订阅或清空全部代理连接。同一规范化控制地址与代理组只能由一个执行器管理；不同地址别名若指向同一个控制器，也应由用户保持代理组独立。本功能针对单实例后端，多个后端实例不能同时管理同一代理组。

## 自动切换规则

- 默认连续两次网络失败后检测当前节点。检测也失败才冷却当前节点并尝试用户勾选的备用节点；检测正常时等待目标网站恢复。
- 故障节点默认冷却 300 秒。全部节点不可用时任务进入等待，保留进度，每 30 秒允许下一次恢复尝试；冷却期内跳过故障节点。
- 控制 API 连接失败、鉴权失败、代理组不存在或切换结果无法确认时暂停该执行器，不能直接将全部节点判为失效。
- HTTP 401/403/429/451 或检测到网站验证页时进入网站冷却，不触发节点切换。源站 5xx 暂时等待；正文解析失败、失败特征仍沿用原有诊断与任务失败保护。
- 自动切换只使用所选具体节点，排除其他代理组、DIRECT、REJECT 等出口。节点改名或被移除后不会自动替换成未选节点。
- 手动切换与采集请求串行，切换前等待当前请求结束，切换后读取实际节点确认。托管请求结束时关闭其专属 Java HTTP 客户端，下一次请求创建新连接，避免复用旧节点隧道。

## 定期轮换

三个条件分别设置为 0 时关闭，可以组合启用，任一条件满足时在下次请求前轮换。至少需要选择两个节点。

| 条件 | 计数方式 |
| --- | --- |
| 时间 | 例如 300 秒。累计执行器采集请求、请求内限速等待及故障处理时间；不累计请求之间的解析、空闲、人工冻结和进程停机时间。最小非零间隔 30 秒。 |
| 章节 | 正文成功保存一次计数；同一任务和章节去重。失败重试、304、目录、待发布和失败特征不计数。 |
| 书籍任务 | 完整采集、正文补全、更新检查任务成功完成时计数；排除单章节任务、目录、元数据、导入和导出任务。 |

顺序轮换按节点列表循环，随机轮换避免立即重复当前节点。成功切换后统一重置三个计数；外部改变节点时，在下次采集核对并重置计数。配置、冷却、去重记录、运行计数和最近 50 条节点事件保存在 PostgreSQL，重启后恢复。

人工冻结期间不执行采集、主动检测和节点切换，解除冻结后继续执行。节点目录浏览仍可使用。运行状态面板可以查看实际节点、计数、等待原因与最近切换记录。

当前延迟检测使用 Mihomo 的单节点 `/delay` 接口，检测目标为 `https://www.gstatic.com/generate_204`；该结果不保证目标小说网站可访问。数据库表由项目现有 Hibernate `ddl-auto: update` 管理，无需新增数据库依赖。

官方参考：[Mihomo 控制 API](https://wiki.metacubex.one/en/api/)、[独立入口配置](https://wiki.metacubex.one/en/config/inbound/listeners/)。
