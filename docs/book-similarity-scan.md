# 书库相似书名扫描

应用版本：`1.45.222`。

## 使用方法

1. 在书库顶部点击“扫描相似书名”。扫描范围为当前账户的整个可见书库，不受当前搜索、筛选或分页影响，不包含回收站和隐藏扫描目录中的书籍。
2. 等待扫描完成，查看候选分组中的书名、作者和文件格式；可打开“详情”核对内容。
3. 取消勾选不应合并的书籍，至少保留两本，点击“合并所选”。
4. 在现有合并窗口选择要保留的目标书籍，核对迁入的全部版本，再确认合并。
5. 合并完成后刷新书库并重新扫描，避免继续展示已经合并的记录。

扫描不会修改书籍。关闭窗口后服务端扫描继续运行；重新打开可获取任务进度。网络错误可重试获取进度，也可以重新扫描。

## 匹配规则

- 统一全角/半角与大小写，忽略空格、标点，去除“精校版”“校对版”“电子版”等常见版本后缀和格式后缀。
- 规范化后同名的书籍进入同一候选组；不少于四个字符的书名按编辑距离匹配，相似度阈值为 80%。
- 数字或明确卷册标记不同的书名不做模糊匹配，减少不同续作、年份或卷册混在一起的情况。
- 不按作者排除候选，方便处理作者缺失或元数据不一致的书籍；已知作者不同会显示提示。
- 分组按相似关系连接，组内两本书可能只分别与第三本相似。因此候选仍需逐本核对，不会自动执行合并。

## 任务与验证

扫描复用当前账户鉴权、书库可见性规则、Caffeine 和现有版本合并接口。后台单线程执行，等待队列有界；每个账户复用正在运行的扫描任务，已完成任务结果临时缓存 30 分钟（最多保留 20 个任务，可能提前淘汰），过期或服务重启后需要重新扫描。没有新增依赖、用户配置或数据库迁移。

自动化验证包括 14 项后端专项测试（匹配规则、穷举对照、真实实体映射查询校验、分页与账户隔离、原有合并流程）以及 390px/1440px 浏览器模拟 API 回归。浏览器回归覆盖后台运行、重新打开、错误重试、分页、键盘勾选、取消确认、正式确认、合并后重新扫描及候选列表无越界。

前端回归命令：

```bash
MOBILE_PLAYWRIGHT_PATH=/path/to/existing/playwright \
MOBILE_BROWSER_CHANNEL=chrome \
npm run test:book-similarity-scan
```

测试默认使用 `http://127.0.0.1:3100`，可通过 `MOBILE_BASE_URL` 指定已有前端服务；使用现有 Playwright，不新增项目依赖。

本机 256 MiB JVM 堆的合成压力检查：30,000 条记录生成 10,000 个预期候选组，约 5.7 秒。该结果不包含数据库读取，也不代表 NAS 实际扫描耗时；尚未进行真实 NAS 书库扫描与合并端到端联调。
