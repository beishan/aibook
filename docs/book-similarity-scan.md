# 书库相似书名扫描

应用版本：`1.45.223`。

## 使用方法

1. 在书库顶部点击“扫描相似书名”。扫描范围为当前账户的整个可见书库，不受当前搜索、筛选或分页影响，不包含回收站和隐藏扫描目录中的书籍。
2. 等待扫描完成，查看候选分组中的书名、作者、来源、格式、章节数和大小；可打开“详情”或点击“对比书籍”核对内容。
3. 取消勾选不应合并的书籍，至少保留两本，点击“合并所选”。
4. 在现有合并窗口选择要保留的目标书籍，核对迁入的全部版本，再确认合并。
5. 合并完成后刷新书库并重新扫描，避免继续展示已经合并的记录。

扫描不会修改书籍。关闭窗口后服务端扫描继续运行；重新打开可获取任务进度。网络错误可重试获取进度，也可以重新扫描。

## 匹配规则

- 统一全角/半角与大小写，忽略空格、标点，去除“精校版”“校对版”“电子版”等常见版本后缀和格式后缀。
- 规范化后同名的书籍进入同一候选组；不少于四个字符的书名按编辑距离匹配，相似度阈值为 80%。
- 数字或明确卷册标记不同的书名不做模糊匹配，减少不同续作、年份或卷册混在一起的情况。
- 不按作者排除候选，方便处理作者缺失或元数据不一致的书籍；已知作者不同会显示提示。
- 分组按相似关系连接，组内两本书可能只分别与第三本相似。因此候选仍需逐本核对，不会自动执行合并。

## 批量合并

分组标题前的复选框用于批量选择；每组内部的书籍复选框决定哪些书参与合并。支持跨页选择、“选中本页分组”和“选择全部结果”。切换页面保留当前扫描的选择；每组至少选择两本书。

点击“批量合并”后，在独立确认窗口逐组选择保留目标。默认建议保留已知章节数较多的书，大小仅作次级参考；这些元数据不能保证正文完整。只有确认后才执行现有版本合并接口，每组选中的源书都迁移全部版本。

分组串行处理，单组使用已有事务。失败会显示具体原因，不会回滚已经成功的其他组；成功、失败和未执行组分别统计。可点击“停止后续合并”，当前组完成后不再执行后续分组；登录失效或权限失败也会停止后续请求。处理后刷新书库并重新扫描，失败或未执行的书籍仍可再次核对。

执行期间请保持浏览器开启。关闭浏览器会中断尚未开始的组，已经提交的组仍可能完成，重新扫描可核对剩余书籍。批量合并不是后台持久化任务。

## 独立书籍与章节对比

“对比书籍”打开独立弹窗。两侧可独立选择组内书籍和文件版本，展示书名、作者、ISBN、出版信息、简介、来源、所选版本大小、已保存章节数及可对比章节数。目录来源显示原始路径；章节数未知时显示“待解析”，不会按零处理。

两侧章节列表可搜索并分页，独立选择章节后并排展示纯文本正文，提示所选文本一致或不同。快速切换时会丢弃迟到的旧响应。文本一致只针对当前所选章节，不表示整本书相同；没有可提取文本时不作一致判断。

支持结构化章节、EPUB、TXT、Markdown、HTML/HTM。EPUB 按正文阅读顺序组织对比章节，不在内存中拼接整本正文；TXT/Markdown 使用现有章节解析器，并保留章节前的前言。PDF、MOBI/AZW3 等暂不支持正文提取的格式仍展示详情，并明确提示，可打开现有阅读器核对。

文本文件对比读取上限为 64 MiB，单章正文最多展示前 50 万字符；超过上限会明确提示，截断内容相同也不会宣称完整章节一致。对比只读取经账户和版本归属校验的书籍，不接收客户端文件路径，不执行合并。

## 任务与验证

扫描复用当前账户鉴权、书库可见性规则、Caffeine 和现有版本合并接口。后台单线程执行，等待队列有界；每个账户复用正在运行的扫描任务，已完成任务结果临时缓存 30 分钟（最多保留 20 个任务，可能提前淘汰），过期或服务重启后需要重新扫描。没有新增依赖、用户配置或数据库迁移。

自动化验证包括 22 项后端专项测试（匹配规则、穷举对照、真实实体映射查询校验、分页与账户隔离、原有合并流程、TXT/EPUB/结构化章节提取、版本归属与超长章节提示）以及 390px/1440px 浏览器模拟 API 回归。浏览器回归覆盖后台运行、重新打开、错误重试、分页、键盘勾选、取消确认、正式确认、合并后重新扫描及候选列表无越界；新增回归覆盖来源/章节/大小、独立对比、版本切换、迟到响应保护、全部/跨页选择及批量部分失败展示。批量执行核心另有串行处理、完整版本迁入、重叠计划拒绝、停止后续及登录失效停止的脚本验证。

前端回归命令：

```bash
MOBILE_PLAYWRIGHT_PATH=/path/to/existing/playwright \
MOBILE_BROWSER_CHANNEL=chrome \
npm run test:book-similarity-scan
```

测试默认使用 `http://127.0.0.1:3100`，可通过 `MOBILE_BASE_URL` 指定已有前端服务；使用现有 Playwright，不新增项目依赖。

本机 256 MiB JVM 堆的合成压力检查：30,000 条记录生成 10,000 个预期候选组，约 5.7 秒。该结果不包含数据库读取，也不代表 NAS 实际扫描耗时；尚未进行真实 NAS 书库扫描与合并端到端联调。
